# astrbot_plugin_diary · 让她自己写日记

给 AstrBot 加一个日记本：它会悄悄记下你们每天聊过的话，到点用她自己的语气写一篇日记，存起来，推给你；之后聊天时，她还能想起自己写过什么。

只依赖 AstrBot 自带接口，不需要额外装 Python 包。

## 它到底做了什么

```
白天：每条消息 → 记进 logs/2026-11-12.jsonl（只有文本，很轻）
23:30：读今天的记录 + 最近两篇日记 + 她的人设
        → 让模型以第一人称写一篇
        → 存成 diaries/2026-11-12.md
        → 发到你在「推送目标」里选的会话
之后：每次她回你消息前，把最近 2 篇日记的前 200 字塞进上下文
        → 她“记得”自己写过什么，能自然提起
```

关键点：**日记是她自己的记忆，不是每天一条定时播报**。所以插件做了三件事——记录、生成、回忆。只做最后一件（定时让 LLM 发一段话）会很像营业。

## 安装与升级

### 从 v1 升到 v2（覆盖安装，数据不会丢）

两种情况都可以：

**A. 插件页上传（推荐）**
WebUI → 插件管理 → 安装插件 → 选 `astrbot_plugin_diary_flat.zip` → 覆盖。
AstrBot 换插件时只替换 `data/plugins/astrbot_plugin_diary/` 这一个目录，
`data/plugin_data/astrbot_plugin_diary/`（你的日记和日志）和 `data/config/` 完全不碰。

**B. 手动替换**
把新文件覆盖到 `data/plugins/astrbot_plugin_diary/`（Docker 版是容器内 `/AstrBot/data/plugins/`），然后重载插件或重启 AstrBot。

升级时自动做了两件事：
1. 旧版 `diaries.jsonl` 里的每一篇，迁移成 `diaries/YYYY-MM-DD.md`（已存在的 `.md` 不覆盖，原 jsonl 保留不删）；
2. 旧配置键 `watch_umos` / `deliver_umos` 自动认成新键 `watch_sessions` / `deliver_to`。

升级后目录长这样：

```
data/plugins/astrbot_plugin_diary/
├── main.py            # 插件主体：记录、生成、定时、指令
├── diary_core.py      # 纯逻辑：存储、提示词、配置项（不依赖 AstrBot，能单独测）
├── webui.py           # 网页接口（9 个路由）
├── metadata.yaml
├── _conf_schema.json  # AstrBot 配置页用的
├── _conf_schema.yaml
├── views/diary/       # 网页界面：index.html + app.js + style.css
└── README.md
```

### 全新安装

插件管理 → 安装插件 → 上传 zip（同上）。或者把文件夹放进 `data/plugins/`，刷新插件列表。

## 网页界面怎么打开

1. AstrBot WebUI → **插件管理**（侧边栏「拓展功能」）
2. 找到 astrbot_plugin_diary，点进插件详情
3. 详情页里有一个叫 **「diary」/ 日记本** 的可视化视图标签，点开就是了

界面长这样：

```
┌──────────────┬──────────────────────────────────────┐
│ 🌙 她的日记本  ⚙│  ‹  2026-11-13  ›      ✦让她写 🗑删除 保存│
│ ＋新的一天  导出│  已写好 · 当天聊了 12 条 · 436 字       │
│ [搜索…]       │  ┌────────────────────────────────┐  │
│ ● 今天 11-13  │  │ 标题                            │  │
│   十一月还有…  │  ├────────────────────────────────┤  │
│   11-12 阴天  │  │ 正文……                          │  │
│   11-11 电波  │  │                                │  │
│ 共 23 篇 …    │  └────────────────────────────────┘  │
│              │  ▸ 那天的聊天记录（12 条，写日记时会用到）│
└──────────────┴──────────────────────────────────────┘
```

能做的事：

| 想干什么 | 怎么做 |
| --- | --- |
| 读某天 | 左边点日期，或用 ‹ › 前后翻 |
| 改错字 / 改语气 | 直接编辑，Ctrl+S 或点「保存」（有未保存时切走会拦一下） |
| 删掉某天 | 详情页「🗑 删除」，二次确认 |
| 让她重写某天 | 「✦ 让她写」——按那天的聊天记录重新生成，覆盖原内容（会先问一次） |
| 补写漏掉的天 | 「＋ 新的一天」或前后翻到空白日期，点「让她写」 |
| 看那天的对话 | 展开底部「那天的聊天记录」 |
| 导出全部 | 左上「⤓ 导出」，得到一个 Markdown 文件 |
| 改设置 | 右上 ⚙，按「基本 / 写作 / 记录与回忆 / 推送 / 高级」分组，保存后立即生效 |

设置里的几个关键项：**她的设定**（persona_prompt，决定像不像她）、**推送目标**（deliver_to，填 `aiocqhttp:FriendMessage:123456789` 这种；页面会提示你「最近一次聊天会话」直接抄）、**时区**（云服务器常是 UTC，一定要 `Asia/Shanghai`）、**写日记时间**（默认 23:30）。

## 指令（QQ 里）

| 指令 | 作用 |
| --- | --- |
| `/日记` | 看今天的日记 |
| `/日记 昨天` / `/日记 11-10` / `/日记 2026-11-10` | 翻某一天 |
| `/翻日记` | 最近写了哪些，一共几篇 |
| `/写日记` | 立刻写一篇（会覆盖当天已有的） |

默认只有管理员能用（`admin_only`），免得群友翻她的本子。

## 数据放在哪

```
data/plugin_data/astrbot_plugin_diary/
├── diaries/2026-11-12.md   # 每篇日记一个文件，人直接能读、能手改
├── logs/2026-11-12.jsonl   # 当天的聊天片段，按「日志保留天数」清理（日记永久保留）
├── state.json              # 上次自动写到哪天、最近的会话
└── webui_prefs.json        # 网页改的设置在写不回配置时的兜底
```

- 备份：把整个 `plugin_data/astrbot_plugin_diary/` 打包带走就行。
- 删插件时如果勾了「删除数据」，这个文件夹会被一起删——注意别手滑。
- 插件目录（`data/plugins/...`）里不放任何数据，所以**随便覆盖升级都安全**。

## 常见问题

**网页里看不到「日记本」标签？**
先确认 `views/diary/index.html` 在插件目录里；然后重载插件（新增视图目录需要重载才被发现）。插件被停用时视图会报 403。

**侧边栏里显示的名字是 `diary`？**
侧边栏标题取自 `.astrbot-plugin/i18n/<语言>.json` 里的 `views.diary.title`，改那个文件即可（目前 `zh.json` / `zh-CN.json` 都设成了「日记」）。视图目录名 `diary` 不改——路由和静态资源路径都挂在它上面。

**到点没写？**
按顺序查：总开关是否开；时区对不对；AstrBot 是否一直在线；模型是否可用。日志里搜 `[diary]`，失败会写原因。网页里也可以直接点「让她写」手动补。

**写得不像她 / 像客服？**
「她的设定」太空。补具体的：她怎么说话、在意什么、有什么小毛病。再不行在「写作风格」里写「句子短一点」「不要用成语」「可以写错别字」。

**日记没发出来，但网页里有？**
推送目标没填对，或者 NapCat 掉线了。发送走的是 AstrBot 的消息平台连接，断线期间不会补发。

**服务器重启会漏写吗？**
不会。启动后检查：今天已过写日记时间且还没写 → 补写；凌晨 0–2 点重启且昨天没写 → 补写昨天。

**报错 `No module named 'diary_core'`？**
那是 v2.0.0 的 bug，升级到 **2.0.1** 即可。原因：AstrBot 把插件当 `data.plugins.<插件名>.main` 这样的子模块导入，插件目录本身不在 `sys.path` 里，所以同目录的 `.py` 不能用普通 `import`。2.0.1 起改为按文件路径加载，模块名挂在插件包下面，重载时能一起清掉。

**群里说的话被写进去了？**
「记录哪些会话」留空就是全记。只想记私聊，就只把私聊的 UMO 加进去。

## 兼容性

- 需要 **AstrBot 4.14+**（网页视图/`register_web_api`）；写日记用 `context.llm_generate`（≥ 4.5.7），更老的版本退回 `provider.text_chat`。
- 网页通过 AstrBot 注入的 `window.AstrBotPluginView` 通信，端点一律写相对路径，插件名由后台转发，不写死。
- 只依赖标准库 + AstrBot 自带模块，没有 `requirements.txt`。
- 多文件插件必须按路径加载同目录模块（见上面的 `No module named` 条目）——这是 AstrBot 的导入方式决定的，不是本插件特例。

## 想更省事？

如果不想装插件，AstrBot 自带**主动型能力 / 未来任务**可以每天定时让 Agent 写段话；但它不会把日记放进聊天上下文，她不会「记得」，而且依赖 Agent 沙盒的文件工具。

另一个现成选择是 `astrbot_plugin_private_companion`，内置日记、日程、主动消息等一整套，功能多但比较重。

这个插件是折中：只做日记这一件事，但把「记录 → 写 → 存 → 想起来」这条线走完整，再配一个能真正翻的本子。
