## 更新

- **v2.0.13** 回忆末尾那段说明精简成四句：只交代「这是背景资料」「别学这里的语气」「别从时间戳推断现在几点」「对方现在说的以对方为准」。原来那五条管太多、像在讲道理，还容易和人格设定打架。
- **v2.0.12** 只保留 `/想想` 手动注入：这段对话第一次说话、`/new`、`/reset`、过每日刷新时间，这四种自动注入全部取消。想让她带回忆，就在那个会话里发一次 `/想想`，只用一次；群里也认。好处是上下文不会自己膨胀，花多少 token 由你决定。「每日刷新时间」「群聊里也带回忆」两项随之停用（留着只为兼容旧配置）。
- **v2.0.11** 额度改成「当前会话七成、其余会话三成」，并把「回填」删掉。回填会把同一天拆成两截接在一起，导致同一段里时间倒流、段首明明写着「更早的略」末尾又冒出更早的话。现在每个会话只装一次、从新往旧连续装，时间线是顺的。
- **v2.0.10** 回忆改回「附加块」（`extra_user_content_parts`）挂载，也就是 v2.0.6 的做法；保留 v2.0.7 的自检日志和「只有真挂上才记今天带过了」，以及同一条消息只注入一次的保险。原因是 `system_prompt`、`prompt`、`contexts` 三个位置都会被 `group_chat_plus` 整段重写，只有附加块它不重建。
- **v2.0.9** 群聊注入默认关闭，新增开关「群聊里也带回忆」（默认关）。原因是查清了群聊里注入一直不生效的根因：`group_chat_plus` 会在我们写完请求之后**整段重写**用户消息正文、上下文列表和人格提示词，并且只保留它「登记在册」的插件内容；我们不在那张名单里（它的逐插件追踪是在自己启动时一次性包住当时的钩子，我们重载之后新注册的钩子它包不到），所以写进去的回忆会在 2 毫秒后被它抹掉。这个开关**带已知 bug**，打开也不保证生效，只适合确认服务器上没有这类插件的场景。私聊不受影响，照旧走 `system_prompt`。
- **v2.0.8** 回忆的挂载点从「用户消息正文」改成「系统提示词末尾」。原因：`group_chat_plus` 这类会重建请求的插件只保留它识别得到的 `system_prompt` / `contexts` / `extra_user_content_parts` 三类通道，写在 `prompt` 里的内容会被它整条替换掉（表现是插件日志说注入了，她的回复却完全没提）。挂在 `system_prompt` 末尾以后，它会把我们列进「检测到第三方插件注入」的清单里并原样保留。
- **v2.0.7** 三处改动。① **回忆改走用户消息正文**（v2.0.8 起改为 `system_prompt`，见上）。② **注入后立刻自检**：成功打一行 `[diary] 注入回忆：已挂到 system_prompt，N 字`；失败打红色 `[diary] 注入回忆失败：内容生成了但没挂上 system_prompt`。③ **只有真的挂上才算「今天注入过了」**：失败不会把当天标记成已完成，下一句还会重试；同一条消息触发两次也只注入一遍。
- **v2.0.6** 两处改动。① **修掉「今天的话没被带上」**：算日期的循环少算了一天，`带几天对话 = 5` 实际只取昨天往前五天，今天的记录一条都没进回忆。改成从今天开始往前数。② **注入时打一行日志**：`[diary] 注入回忆：日记 5 篇（11月18日~11月22日） · 当前对话 3 段（11月23日~11月21日）其他对话 · 0 段 · 9104 字`，一眼能确认这次带了没有、带的是哪几天。
- **v2.0.5** 三处改动。① **段落带上日期**：以前段头只有「私聊·你 · UMO」，同一个人五天的记录长得一模一样，模型分不清哪段是哪天；现在写成「【11月22日 · 私聊·你 · UMO】」。② **额度按会话分配**：当前会话先拿一半，按天从新往旧装、装满为止（不再每段硬砍 1500 字），剩下的另一半平分给其他会话，还有剩就回填；只有一个会话时整份额度都归它。出厂默认额度从 8000 提到 10000。③ **旧日志不再重复投递**：某天已经有转换后的会话文件，就不再读那天的旧单文件。附带修了群消息 QQ 号一直为空的问题（AstrBot 的 `get_sender_id()` 只认 `str`，而 NapCat 传的是 `int`）。
- **v2.0.4** 回忆不再每次聊天都注入：只在「这段对话第一次说话」「`/new`、`/reset` 之后」「过了每日刷新时间」三种时机带一次。日志改成按会话分文件（`logs/日期/私聊·名字.jsonl`），带 `_head` 头、昵称、群里的 QQ 号；旧日志自动迁移并保留原件。新增 `/想想`。
- **v2.0.3** 修掉「点『让她写』『删除』没反应」：AstrBot 的插件页 iframe 沙箱里 `window.confirm()` 会被静默吞掉，改成页面内自制确认框。修掉「开关插件报 500」：`terminate()` 里 `await` 被取消的任务会抛 `CancelledError`，而 AstrBot 那次调用没有兜底。
- **v2.0.2** 修复网页里点「保存」报 `当前AstrBot版本不支持apiPut请求`、点「删除」没反应：AstrBot 注入的页面 bridge 只有 `apiGet` / `apiPost`，写操作改为全部走 POST，后端同时补了 POST 版删除路由。
- **v2.0.1** 修掉装了之后报 `No module named 'diary_core'`：AstrBot 用 `data.plugins.<插件名>.main` 的方式导入，插件目录本身不在 `sys.path` 里，同目录模块必须按路径加载并按包名注册。
- **v2.0.0** 拆成多文件（`main.py` 薄壳 + `diary_core.py` 逻辑 + `webui.py` 网页接口 + `views/diary/` 前端），加可视化界面。

## 这是什么

三个能力：

1. **记**：你和她说话，她顺手记下（按会话分开存，谁说的、几点说的、QQ 号都有）
2. **写**：每天到点（默认 23:30），她翻一遍当天的记录，用她自己的人格写一篇日记
3. **想**：一段对话开始时，把最近几篇日记和最近几天的聊天记录塞进她的上下文，让她能接上之前的事

日记是「她以第一人称写的」——不是流水账，是带情绪和取舍的那种。

## 怎么装

**方式一：面板上传（推荐）**

1. AstrBot 后台 →「插件」→「安装插件」→ 上传 `astrbot_plugin_diary_flat_v<版本>.zip`
2. 安装完点「重载插件」（新增的网页视图要重载才会出现）
3. 进入插件详情页，打开叫「日记」的视图

**方式二：手动放目录**

```bash
cd /path/to/astrbot/data/plugins
unzip -o astrbot_plugin_diary_flat_v<版本>.zip -d astrbot_plugin_diary
# 然后重启 AstrBot 或在面板里重载插件
```

Docker 部署的话，先 `docker cp` 进容器再解压。

**装完先配三项**（插件详情页 →「设置」）：

| 项 | 说明 |
|---|---|
| 她的名字 | 写日记时自称用 |
| 写日记用的模型 | 留空则用当前会话的模型 |
| 记录哪些会话 | 留空 = 所有跟她说过话的会话都记 |

## 网页里能做什么

- **日历**：哪天有日记一目了然，点日期看内容
- **看/改**：正文可以直接编辑保存，也能改标题
- **删**：删掉某天的日记（会二次确认）
- **让她写**：没写或想重写的日子，点一下当场生成
- **看记录**：某天各会话的原始聊天记录，按会话分组
- **导出**：把所有日记导成一个 markdown 文件

## 指令

| 指令 | 说明 |
|---|---|
| `/日记` | 看今天的日记 |
| `/日记 昨天` | 看昨天的（也支持 `前天`、`11-10`、`2026-11-10`） |
| `/翻日记` | 看最近几天的标题 |
| `/写日记` | 立刻写一篇（没到点也能写，用于测试） |
| `/想想` | 让她把最近的日记和聊天重新读一遍（下次对话生效） |

除 `/日记` 系列外都需要管理员权限（可在设置里关掉 `admin_only`）。

## 配置项

**基础**：启用、写日记时间、时区、她的名字、用哪个人格、人格补充、生活设定、文风补充、日记字数、用哪个模型。

**记录与回忆**：

| 项 | 默认 | 说明 |
|---|---|---|
| 记录哪些会话 | 空 = 全部 | 只有选中的会话才会被记录 |
| 带几篇日记 | 2 | 回忆里放最近几篇日记（每篇最多 200 字） |
| 带几天对话 | 1 | 回忆里放最近几天的聊天记录 |
| 回忆额度（字） | 10000 | 日记 + 对话的总字数上限 |
| 每日刷新时间 | 04:00 | **已停用**：不再按时间自动带回忆，留着只为兼容旧配置 |
| 回忆范围 | 全部会话 | 只当前会话 / 当前会话+所有私聊 / 全部会话 |
| 私聊内容可以出现在群里 | 关 | 打开后群里的回忆也会带上私聊的话 |
| 群聊里也带回忆 | 关 | **已停用**：现在群聊和私聊一样，发 `/想想` 就带 |
| 升级时自动转换旧日志 | 开 | 把 v2.0.3 及更早的单文件日志拆成按会话的文件 |
| 旧日志参与回忆 | 开 | 旧单文件里的记录是否也进回忆 |

**写日记时参考哪些会话**：留空 = 全部（含旧日志）；选中后只参考选中的会话。

## 回忆是怎么带进去的

### 只有你喊她，她才带（v2.0.12 起）

**自动注入全部取消了**：这段对话第一次说话不会带，`/new`、`/reset` 之后不会带，过了每日刷新时间也不会带。

只有一种情况会带：**你在那个会话里发 `/想想`**。她回一句「我都记起来了」，从下一句话开始带上最近的日记和聊天；带过一次就失效，想再要就再发一次。群里也认（群里发一次，群里下一次回复就带）。

这么做的好处是上下文不会自己膨胀，什么时候花这笔 token 由你决定。

> 已知问题：装了 `group_chat_plus` 的服务器上，群里那次可能被它抹掉——它会在我们写完请求之后整段重写用户消息、上下文和人格提示词，只保留它「登记在册」的插件内容，而它只包装自己启动时已有的钩子。表现是插件日志说注入成功、她的回复却完全没提。私聊不受影响。

### 带什么

- 最近 N 篇日记，每篇截前 200 字
- 最近 N 天的聊天记录，按会话分段，段头带日期

额度怎么分：当前会话先拿七成，按天从新往旧连续装、装到额度用完为止；剩下的三成平分给其他会话。**没有回填**——回填会把同一天拆成两截，接在一起会让时间倒流。只有一个会话时，那三成没人分，就空着。

### 挂在哪里（重要）

回忆不是塞进对话历史，而是**追加到系统提示词（`system_prompt`）的末尾**，只在这一轮请求里存在。

为什么不用另外两个位置：

| 位置 | 问题 |
|---|---|
| `extra_user_content_parts`（附加内容块） | 有些群聊增强插件重写上下文时不做这一块的保留，内容会丢 |
| `prompt`（用户消息正文） | `group_chat_plus` 会用缓存里的原文重建整条用户消息，我们改过的正文被整条替换掉 |
| `contexts`（作为一条额外消息） | 会写进历史，之后**每一轮**都带着这 9 千字，token 一直重复算 |

`system_prompt` 是 `group_chat_plus` 明确会「差分保留」的通道（它会在日志里打印「检测到第三方插件注入：… system_prompt文本」），而且只影响当轮，不会每轮重复计费。

代价是：回忆不进历史，事后再翻聊天记录看不到它。这是有意的取舍。

### 怎么确认它真的进去了

三层验证，从弱到强：

1. **我们自己的日志**
   ```
   [diary] 注入回忆：日记 5 篇（11月18日~11月22日） · 当前对话 3 段 · 9160 字
   [diary] 注入回忆：已挂到 system_prompt，9427 字
   ```
   这只能证明我们写进去了，不能证明没被别的插件丢掉。

2. **`group_chat_plus` 的兼容增强清单**（只在打开了「群聊里也带回忆」时才有意义）
   ```
   [兼容增强] 检测到 5 个第三方插件注入:
     meme_manager: system_prompt文本
     astrbot_plugin_diary: system_prompt文本      ← 要看到这一行
   ```
   它看得见的内容才会保留；看不见的会被它重建请求时丢掉。v2.0.9 起群聊默认不注入，所以群聊里**看不到**这一行是正常的。

3. **她自己说出来**：问一句「你前几天写过什么」，看她能不能提到日记里的事。这一层最直观，但也最随机。

> 两个常见误判：① 回忆不进历史，**在聊天记录里搜不到 `【回忆】` 是正常的**；② 群聊里没有注入日志，是因为 v2.0.9 默认关闭了群聊注入。

### 末尾那段说明（v2.0.13 精简）

回忆正文末尾会附四句话，只有两个作用：告诉她这是**背景资料**（不用一条条讲、别说"我记得"），以及别学这里的语气和说话方式、别从时间戳推断现在几点、对方现在说的以对方为准。

```text
下面是你记得的、之前发生过的事，当背景资料看，不用一条条讲出来，也不要说"我记得"。
聊天照人格设定说话，别学这里面的语气和说话方式。
不要从里面推断现在几点、今天几号。
对方现在说的和你记得的不一样，以对方为准。
```

想进一步减少"被日记带文绉绉"的影响：把「带几篇日记」调小（日记是书面体，最容易带偏；聊天记录是她自己的口语，学它没坏处）。

## 文件放在哪

都在 `data/plugin_data/astrbot_plugin_diary/`：

```
diaries/2026-11-22.md          每篇日记一个文件（人可读）
diaries.jsonl                  日记索引（兼容旧版，自动迁移成上面的 md）
logs/2026-11-22/
    私聊·冬霂.jsonl             每个会话一个文件，首行是 _head
    群·摸鱼小分队.jsonl
logs/2026-11-22.jsonl          旧版单文件日志（迁移后保留，只当素材）
sessions.json                  会话对照表（UMO → 可读文件名）
state.json                     注入状态、最后说话的会话
```

日志文件长这样：

```json
{"_head": 1, "umo": "aiocqhttp:GroupMessage:987654321", "name": "群·摸鱼小分队", "since": "2026-11-23"}
{"t": "13:20", "q": "67890123", "n": "小红", "m": "摸鱼摸到半夜"}
{"t": "13:25", "bot": "霖霏", "m": "那我去楼下便利店看看"}
```

- 首行 `_head` 记这条对话的来源；后面的行不再重复
- 有 `bot` 字段 = 她说的（值是当时的自称）
- `q` 只在群聊里有（私聊不存 QQ 号）
- 文件名第一次创建时定下来，之后改名也不会变（防止同一个会话被劈成两个文件）

**备份**：整个 `astrbot_plugin_diary` 目录拷走即可。**升级**：覆盖安装只替换插件代码，`plugin_data` 和配置都不动。

## 常见问题

**侧边栏里显示的名字是 `diary`？**
v2.0.1 起用 `.astrbot-plugin/i18n/zh-CN.json` 改成了「日记」，升级后重载插件即可。目录名仍是 `views/diary/`（路由挂在这上面，改了就失效）。

**点「保存」报 `当前AstrBot版本不支持apiPut请求`？**
v2.0.1 及更早的版本会这样，升级到 **2.0.2** 即可。AstrBot 注入给视图的 bridge 只有 `apiGet` 和 `apiPost` 两个方法（没有 PUT / DELETE），2.0.2 起保存和删除都走 POST。

**点「让她写」「删除」没反应，连确认框都不弹？**
v2.0.2 及更早会这样。AstrBot 插件页的 iframe 沙箱只开了 `allow-scripts allow-forms allow-downloads`，没有 `allow-modals`，浏览器会静默忽略 `window.confirm()` 并返回 `false`。2.0.3 起改成页面内自制确认框。

**开关插件时报 500 / Internal server error？**
v2.0.2 及更早会这样。`terminate()` 里取消后台任务后 `await` 会抛 `CancelledError`，而 AstrBot 的 `_terminate_plugin` 没有 try/except，异常一路冒到接口层。2.0.3 起自己吃掉这个异常。

**安装后报 `No module named 'diary_core'`？**
v2.0.0 会这样。AstrBot 以 `data.plugins.<插件名>.main` 导入插件，插件目录不在 `sys.path` 里，同目录模块必须用 `importlib.util.spec_from_file_location` 按包名注册。升级到 2.0.1 即可。

**日志里说注入了，她的回复却没提到？**
分两种：私聊里先看有没有 `[diary] 注入回忆：已挂到 system_prompt，N 字`，有就说明写进了请求（是否被别的插件吞掉要看对方日志）。群聊里 v2.0.9 起**默认不注入**，没有注入日志是正常的——想试就在设置里打开「群聊里也带回忆」，但那个开关带已知 bug：装了 `group_chat_plus` 时会被它重写掉。

**群聊里怎么不带回忆了？**
v2.0.9 改的。群聊注入在装了 `group_chat_plus` 的环境里被证实无效（它的逐插件追踪包不到我们重载后的钩子，写进去的内容会被它重建请求时抹掉），所以先默认关掉，等找到稳定通道再开。群里的聊天记录照常保存，写日记时照样能用到。

**她怎么不记得昨天说的话了？**
回忆只在三种时机带一次，之后靠对话本身延续。想让她重新读一遍就当天的记录，发 `/想想`。

**回忆里能装下多少天的对话？**
总量由「回忆额度（字）」控制，默认 10000 字（约 3000 token）。按实际聊天密度，一个人一天大概 1000–6000 字，所以通常能装 2–5 天。额度越大越完整，但每轮成本也越高。

**旧日志会被丢掉吗？**
不会。升级时自动转换到新结构，旧文件原地保留。想重新生成回忆结构的话，删掉 `logs/` 下的日期目录即可（旧日志还在）。

**群里会带上别人的聊天记录吗？**
默认「回忆范围 = 全部会话」，会。担心串台就把「私聊内容可以出现在群里」关掉，或者把范围改成「只当前会话」。

**日记能改成第二人称或别的文风吗？**
可以，「文风补充」里写清要求，比如「用第三人称、少用比喻、结尾不要总结」。

## 兼容性

- AstrBot **4.14.0** 及以上（`on_llm_request` / `on_llm_response` 钩子、`llm_generate`、`register_web_api`）
- 已适配 AstrBot 4.29.x
- 与 `group_chat_plus` 共存：私聊注入挂在 `system_prompt`；**群聊注入默认关闭**（它的重写会覆盖我们的内容，属已知 bug）
- 网页通过 AstrBot 注入的 `window.AstrBotPluginView` 通信，端点一律写相对路径，插件名由后台转发，不写死；写操作只走 `apiGet` / `apiPost`（bridge 不保证有 `apiPut` / `apiDelete`）
- 不支持同一实例里装两份（数据目录同名）
